# 首頁守備配置圖：指定資產與防回歸規範

## 指定資產

首頁「守備位置配置（平板雙欄與觸控優化）」元件只可使用使用者指定的原始檔案：

| 項目 | 固定值 |
| --- | --- |
| 正式檔案 | `assets/images/istockphoto-1269757192-612x612.jpg` |
| 圖片尺寸 | 612 × 535 像素 |
| SHA-256 | `3e54016b59f580b01c1bfb4a207118ffac237cf6beefdb681b216472ce157b31` |
| 程式常數 | `HOME_DEFENSE_FIELD_IMAGE`（`constants/baseball-assets.ts`） |

## 本次根因

先前的修正錯誤地追查到另一條「新增場次」的圖片引用鏈，沒有命中使用者截圖中首頁的 `TopDownLineupField`／`FieldCard` 守備位置配置元件。該實際元件仍以程式繪製綠色球場、壘線與內嵌守備位置圖形，因此即使其他圖片資產已替換，首頁畫面仍會顯示舊球場。另有多個別名資產及直接引用，使正式圖片來源不明確；正方形容器的預設 `cover` 顯示方式亦可能裁切 612 × 535 的原始比例。

## 永久修正

使用者截圖中的 `TopDownLineupField`／`FieldCard` 現已改為只引用集中管理的 `HOME_DEFENSE_FIELD_IMAGE` 常數，並移除該元件程式繪製的綠色球場背景。資產目錄僅保留原始檔名，圖片使用 `contain` 維持原始比例，守備標記依附圖的本壘下方、一壘右側、二壘上方、三壘左側校準。`tests/baseball.scoring.test.ts` 會以「守備位置配置（平板雙欄與觸控優化）」文字錨點鎖定實際首頁元件，同時驗證背景常數、禁止舊程式球場、禁止舊別名、正式檔案雜湊與完整圖片顯示模式。日後若要更換圖片，必須同步更新本文件、常數、實際元件測試與測試雜湊。
