# 單場整體紀錄表：早稻田式版型投影準則

本文件只整理使用者提供之復興67比賽紀錄 PDF 與 2013 WBC 表格的**版面結構**。它不匯入、推測或覆寫任何 PDF 內的比賽事件、比分或統計資料；2013 WBC 表格第七局的已知錯誤不作為規則來源。

## 固定版面骨架

| 區域 | 顯示原則 | 資料來源 |
|---|---|---|
| 主列 | 先發第 1 至第 9 棒依棒次直向排列，每一棒次為一個可辨識的大格。 | `GameLineup.battingOrderIds` |
| 候補列 | 每一棒次預留先發後的候補子列，用來承接代打、代跑、換投、換守等局中人員。起始至少保留兩個候補格；超出時可增加，不可遺失。 | `Substitution` 鏈結與球員名單 |
| 局欄 | 每局以實際發生的打席為準，最少顯示三個打席槽；當該局超過九個人次時持續延展。 | `AtBatEvent` |
| 換人 | 換人從其發生局數起，落在原棒次的下一個候補子列。不同棒次可在不同局數開始，故視覺上自然錯位。 | `Substitution.inning`、`half`、`timestamp` |

## 投影安全規則

1. 每一個顯示打席都必須直接指向唯一的 `AtBatEvent.id`；空白槽只代表尚未有事件，不能建立虛構事件。
2. 投影只改變「單場整體紀錄」的呈現，不重算或改寫比分、出局、壘包、逐球、跑壘、正式打擊或投手統計。
3. 已有的 `recordCorrection` 僅在對應的原始打席格上顯示，沿用既有的安全鎖、預覽與確認流程。
4. 沒有每場先發棒次資料的舊場次必須仍可顯示：以實際打席的首次出現順序建立保守的棒次列，且不得更動原場次資料。

## 互動與閱讀準則

橫式工作台使用可水平捲動的局欄。左側保留棒次、先發守位、入出局摘要、背號與球員資訊；每一個實際打席格均可開啟既有詳細資訊與事後補正流程。完整換人歷程仍保留在表格下方，作為投影的可追溯佐證。
